# Project View

A **project** is the primary way to organize tasks in Ultra Tasks. Every task belongs to exactly one project, making projects the main organizational structure for your work.

## What Projects Are

Projects are self-contained workspaces. Each project has:

- **Task lists** — Active tasks and an optional backlog
- **Notes** — Project-specific notes
- **Color and icon** — A theme color and an icon to tell projects apart
- **Integrations** — Issue trackers (like Jira or GitHub) can add their tasks to a project; they are set up in the issue provider panel, not in the project's settings (see [[2.07-Manage-Task-Integrations]])

When you switch to a project view, you see only the tasks that belong to that project, along with the project's notes and settings.

## Projects Vs Tags

Projects and tags serve different organizational purposes:

| Aspect                    | Projects                                                         | Tags                                                |
| ------------------------- | ---------------------------------------------------------------- | --------------------------------------------------- |
| **Relationship to tasks** | Each task belongs to exactly **one** project (required)          | Each task can have **zero or more** tags (optional) |
| **Purpose**               | Primary organizational structure — every task has a home project | Secondary labels for cross-cutting categorization   |
| **Features**              | Backlog, notes, color and icon, integrations                     | Simple labels for filtering and grouping            |

A task must always belong to a project. Tags are optional labels you can add to tasks across different projects to create cross-cutting categories.

## Project Features

**Backlog**: Projects can have a separate backlog list for tasks you're not actively working on. You can move tasks between the active list and the backlog.

**Sections**: In the default project task list, hover or focus before, between, or after existing sections to reveal **Add section**. When no named sections exist, the same control appears after the default task list, including in Inbox. Enter a name in the dialog to create the section at that position. The project menu and main menu still offer **Add section**, including on touch devices and when no sections exist.

**Notes**: Each project can have its own notes, separate from task notes. Open the notes panel with the notes button in the header or `Shift+N` (on phones, tap **Browse** in the bottom bar and choose **Project Notes**); `Alt+N` adds a new note (see [[3.03-Keyboard-Shortcuts]]). Notes use Markdown; click a note to edit it in a fullscreen editor, and drag notes to reorder them. The sun button on a note pins it to Today, so it also appears in the notes panel of the Today view. A note's **⋮** menu moves it to another project, turns Markdown rendering of its preview off or on, or deletes it. Project notes can be switched off under **Settings → General → App features**.

**Color and icon**: Each project has a theme color and an icon (emojis work too), set as **Theme color** and **Icon** in the project's settings, to help you visually distinguish projects.

**Integrations**: Issue trackers (like Jira, GitHub, GitLab) are connected in the issue provider panel. Each integration can add the tasks it imports to a default project; see [[2.07-Manage-Task-Integrations]].

## Organizing Projects

Projects themselves are **flat** — there are no parent projects or subprojects. A project cannot contain other projects.

However, you can **organize projects into folders** in the navigation menu. Folders can be nested (folders within folders) to create a hierarchy for navigation, but this is purely for organization — it doesn't change how projects work or how tasks are stored.

You can move projects between folders without affecting the tasks or any other project data.

## Project Layouts

The **Project view** button in the top-right corner switches how the current project is shown. Its icon reflects the selected view; the menu marks that view with a checkmark:

- **List** — The normal task list (the default).
- **Board** — The project's [sections](#moving-tasks-between-sections) as columns (see below).
- **Calendar** — The [[4.04-Schedule-View]] (the **Calendar**) narrowed to this project: only this project's tasks and repeating tasks, and new tasks you create there belong to this project.
- **Upcoming** — The [[4.03-Planner-View]] (**Upcoming**) narrowed to this project in the same way.

In the Calendar and Upcoming layouts, events from your iCal or calendar providers are hidden, because they do not belong to a project. Turn on **Show calendar events** in the same menu to include them.

The layout is a display preference of this device. It is remembered per project on this device only and is not synced, so each device (and each project) can use a different layout.

### Board layout

The Board layout shows one column per section, with a **No section** column first for tasks that are in no section, and an **Add section** column at the end. Each section column shows its title and task count, and has a pencil button to rename the section. Add a task at the top of a column with its **Add** button; a task added to a section column joins that section.

Drag a task to another column to move it there. A task is in at most one section, so moving it to a section takes it out of its previous one; dropping it in **No section** takes it out of its section. Dragging within a column reorders it. Only open tasks appear on the board, as in the List layout.

This is not the [[4.05-Board-View]]: that page's boards group tasks by tag and project filters across all your projects, and keep their filter settings and edit button. The project Board layout has no filters of its own; its columns are the project's sections.

## Hiding Projects

When a project is active but you do not want it in the sidebar project list, enable **Hide project from sidebar** in the project settings or use the Projects visibility menu in the sidebar.

Hiding a project changes navigation only. The project stays active, and its tasks can still appear in cross-project task views such as Today, Upcoming, Calendar, Boards, and Search. Project navigation helpers, including project short syntax, do not match hidden projects.

## How Tasks Belong to Projects

Every task has a project assignment. When you create a task, it's assigned to the current project (or the Inbox if you're in a tag context without a default project). You can change a task's project by:

- Dragging and dropping the task to another project in the navigation
- Editing the task and selecting a different project

When you view a project, you see all tasks that belong to it. When you view a tag, you see tasks from multiple projects that have that tag, and each task shows its project as a badge.

## Moving Tasks Between Sections

In a project or Inbox with sections, select tasks and choose **Actions → Move to section**. Choose a section or **No section (project root)**. Tasks are appended in their displayed order; tasks already at the destination stay in place. Subtasks follow their parent and cannot move independently. Backlog tasks must first be moved to the regular project list.

The same menu is available from a selected task's context menu, including keyboard and touch selection.

## Dragging Several Tasks

Use Ctrl/Cmd-click or Shift-click to select tasks. Drag a selected parent task to move the selected parent tasks together. Drop them into a section or the project root at the desired position, preserving displayed order, or onto a project in the sidebar. Subtasks follow their parent. Sidebar moves use the existing confirmation for recurring tasks and move their recurring configuration together.

The drag preview shows the number of selected parent tasks. Group drops into subtasks, tags, schedule, done, or backlog lists are not supported. Touch selection continues to use the Actions menu; a normal click clears selection, and dragging an unselected task still moves just that task. Outside project views, such as Today or a tag, dragging a selected task within the list moves just that task, while dropping it on a sidebar project moves all selected tasks.

## Completing Projects

When you finish with a project, you **complete** it to retire it from your active workflow and celebrate the result. Right-click the project in the sidebar (or click the `⋮` button; on touch devices, long-press the project) and choose **Complete project**.

If the project still has **unfinished tasks**, you're asked what to do with them first: **Move to Inbox** (the default — they stay actionable), **Mark as done**, or **Cancel**. Before the project is completed, a final confirmation asks you to confirm the action.

On completion you get a full-screen **celebration** with a short summary — tasks done, time tracked, days worked, and how many days the project ran from its first worked day to completion (time-based stats are hidden when you don't track time).

A completed project becomes fully **dormant** — all its data is preserved, but it stops generating noise across the app. Specifically, it:

- Is removed from the sidebar project list and the main visibility checklist
- Has its tasks hidden from Today, Tags, Boards, From previous days, Deadline, and Scheduled views
- Has its repeating tasks suspended — no new instances are generated
- Has its reminders suppressed — no notifications fire for its tasks

**Finding and reopening** completed projects: click **Archived** at the bottom of the sidebar Projects list. The entry is there while at least one project is archived and shows how many are. On that page, completed projects appear with a trophy badge and their completion date. Use the **Reopen** action there to clear the completed state and bring the project back to the sidebar with all tasks, repeating configs, and reminders active again.

# Manage Task Integrations

This how-to describes how to set up and use issue integrations (Jira, GitHub, GitLab, and others) and calendars to import and link tasks from external systems. For an overview of how integrations work, see [[4.24-Integrations]]. For a comparison of which provider supports worklogs, status transitions, subtasks, and other features, see [[3.07-Issue-Integration-Comparison]].

## Open Integrations

Open **Integrations** in the main navigation, below **Upcoming** and **Calendar**. It shows imported and synced tasks from every connection and project. On phones, open **Browse** to reach the same page. There is no separate integrations side pane or App features toggle.

**With the keyboard:** Use **Open Integrations** (default **P**); existing shortcut assignments continue to work. See [[3.02-Settings-and-Preferences]] → Keyboard and [[3.03-Keyboard-Shortcuts]].

## Add an Integration

1. Open **Integrations** and choose **Connect account**.
2. Choose the provider and complete its supported sign-in or credential form. Provider-specific scope, advanced settings and **Test connection** remain in this form.
3. Choose **Import** for independent snapshots, or **Sync** for ongoing updates using the fields that the connector supports.
4. Create a local destination project or choose an existing one.
5. Review the provider's behavior and each field direction, then choose **Save connection**. New connections start with receive-only directions; choose write-back explicitly where supported.

For **Plainspace** collaboration, you can also use the project menu — see [Collaborate on a Project with Plainspace](#collaborate-on-a-project-with-plainspace) below.

If a Google Calendar time-block write fails because this device is not connected, the error notification offers **Connect**. It opens that calendar integration's settings, where you can connect the Google account on this device. Other write failures keep their usual error notification.

### Calendar Integrations: iCal Vs CalDAV (e.g. Nextcloud)

**iCal** and **CalDAV** are two different integrations and need **different link types**:

- **iCal (Calendar):** Use a **subscription** or **export** URL. No login. The app shows **events** (VEVENT) in the Calendar/Upcoming. In **Nextcloud**, use **“Copy subscription link”** and paste it into **“URL of the iCal source”** in the app. Do **not** use “Copy private link” for iCal—that is for CalDAV.
- **CalDAV:** Use the **CalDAV URL** for your user and calendar, and enter **username and password**. The app shows **tasks/todos** (VTODO). For already-imported VTODOs, completion status, title, and notes can each be configured as **off**, **pull only**, **push only**, or **both**. New top-level tasks added in the provider's default project can optionally be uploaded as new VTODOs (**Create a CalDAV task for each new task in the default project**, off by default; subtasks and repeating tasks stay local, and the category filter, if set, is added to the VTODO). Deleting a linked task can optionally delete its VTODO on the server too (**Delete the CalDAV task when the linked task is deleted**, off by default). Undo, or restoring the task from Recently deleted, within the undo period keeps the VTODO; a later restore does not bring it back. In **Nextcloud**, use **“Copy private link”** (or the CalDAV calendar URL, e.g. `…/remote.php/dav/calendars/<USER>/<CALENDAR>/`). Do **not** use the subscription link for CalDAV.

If the integration “doesn’t work,” check that you used the right link and the right provider (iCal vs CalDAV). For more detail see [[4.24-Integrations]] and [[3.07-Issue-Integration-Comparison]].

For **CalDAV Events** calendar lists, enter the server URL, username, and password first, then click **Load Options** before choosing calendars. The calendar dropdowns stay disabled until options are loaded. Both the server root (for example, `https://host/remote.php/dav` for Nextcloud) and a specific calendar-home URL are supported. If no calendars are found, check the credentials and confirm that the account has at least one event calendar available.

After saving, the connection appears in the page’s **Source** list. You can have multiple accounts or scopes for the same provider; the source scope identifies each connection.

### Azure DevOps and Self-Hosted TFS URLs

For **Azure DevOps**, enter the full organization or collection URL in **Host**. For Azure DevOps Services this looks like `https://dev.azure.com/<organization>`. For self-hosted Azure DevOps Server/TFS this can include the collection path, for example `https://server:8080/tfs/DefaultCollection`. The separate **Project** field is still required.

## Add an Issue or Calendar Item as a Task

1. Open **Integrations** and choose **Browse source items** for the connection.
2. Enter a query and choose **Search source**. Search syntax depends on the provider.
3. Choose **Import** or **Sync**, select the items, and choose **Add selected items**. You can optionally copy available source labels as local tags.

The resulting tasks use the connection's destination project and remain ordinary UltraTasks tasks. They appear in automatic Imported/Synced sections without creating additional copies. Calendar events also remain available in Upcoming and Calendar through their existing connection workflows.

## Edit or Reconfigure an Integration

Choose **Connection settings** beside the connection in the **Source** list. You can edit credentials, enable or disable the connection, change advanced options, duplicate it, or delete it. A deleted connection does not delete the local tasks.

If Plainspace rejects its token or the server needs an update, the connection list displays the existing reconnect or compatibility notice.

## Set a Default Project for an Integration

Choose the local destination during setup, or open **Connection settings** and change the default project. Provider-specific scope, such as a Jira project or GitHub repository, stays in the same credential form.

## Add Existing Issues from the Add Task bar (search mode)

You can also add issues (and existing tasks) directly from the add task bar:

1. Open the **add task bar** (e.g. **Shift+A** or the “Add new task” button).
2. Click the **search** icon or press **Ctrl+1** to switch to **issue search** mode. The placeholder becomes “Add existing task or issues…”.
3. Type to search across configured providers and your tasks/archive. Select an issue from the list to add it as a linked task in the current context.

See [[2.03-Add-Tasks]] for more on the add task bar and search mode.

## Collaborate on a Project with Plainspace

[Plainspace](https://plainspace.org) is Ultra Tasks's optional collaboration layer: it turns a local project into a **shared Space** so you can work on it with others. Tasks assigned to you import automatically, and done state, title and scheduled time stay in sync both ways (changes made in Plainspace pull in on the next poll). This is a network feature — task data in a shared project leaves your device; your other projects and core offline use are unaffected.

**Share an existing project:**

1. Open the project's **context menu** (the **⋮** menu next to the project in the sidebar, or the project header menu).
2. Click **Collaborate on Plainspace**.
3. If you haven't connected yet, a guided dialog asks for your email and then the 6-digit code Plainspace emails you; a new account also asks for your name and gets a first Space named after the project, linked directly (skipping the next step). **Use the browser instead** lets you paste an **API token** (`pat_…`) created in Plainspace instead.
4. Choose to **create a new Space** for this project or **link an existing** one, then confirm. A bound Plainspace provider is created and tasks assigned to you start importing.

**Share at creation time:** When creating a project, enable **Collaborate on this project on Plainspace** in the create-project dialog to do the same in one step.

Once a project is shared, the **Collaborate on Plainspace** menu item is hidden for it and **Copy invite link** takes its place: it copies the Space's address to send to the people you want to work with. Unclaimed tasks in the Space appear in a **claim pool** in the work view, where you can claim them into your own list.

**Deleting a shared task** deletes it in Plainspace too, for everyone in the Space. When you delete it in the app, Ultra Tasks always asks first, even if **Confirm before deleting tasks** is turned off. The exception is a task that is no longer in your Plainspace list (unassigned or removed there): deleting it removes only the local copy, and the app asks first only if **Confirm before deleting tasks** is on. Plugins and the local REST API delete without asking. After deleting a single task you can still undo for a few seconds. Deleting several selected tasks at once has no undo.

## Project-level Integration Settings

**Project settings** have no integration section. Integrations are set up on the Integrations page; to tie an integration to a project, set its default project in the provider's settings (see [Set a Default Project for an Integration](#set-a-default-project-for-an-integration) above). Provider-specific options such as which Jira project or GitHub repository to use are in the same settings dialog.

## Troubleshooting

- **No issues in search / “Check your config!”:** Open the provider’s **Connection settings** and check host URL, token, and project/repo ID. Test the connection if the dialog offers it. For Jira in the **web app**, a browser extension may be required; check the connection guidance in the credential dialog.
- **Connection is disabled:** Open **Connection settings** in the Source list to enable it again.
- **Issues not updating:** Some providers poll for updates on an interval. Check the provider’s configuration for options like “Check for updates every X” or polling interval. Select synced tasks on the Integrations page and choose **Refresh selected** for a manual update.

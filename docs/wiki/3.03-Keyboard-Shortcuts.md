# Keyboard Shortcuts

Ultra Tasks supports an extensive keyboard shortcut system. Shortcuts are grouped by function, and most are user-configurable under **Settings → General → Keyboard shortcuts** ([[3.02-Settings-and-Preferences]]).

## Functional Grouping

Configurable shortcuts fall into these categories:

- **Global (system-wide):** `globalShowHide`, `globalToggleTaskStart`, `globalAddNote`, `globalAddTask`, `globalToggleTaskWidget`. Available only in the Electron/desktop build.
- **Navigation:** `goToFocusMode`, `goToWorkView`, `goToScheduledView`, `goToPlanner`, `goToTimeline`, `goToSettings`.
- **Task management:** `taskToggleDone`, `taskAddSubTask`, `taskSchedule`, `taskDelete`, `taskEditTitle`, move/select task actions, and others.
- **UI panels:** `toggleIssuePanel`, `toggleBacklog`, `toggleTaskViewCustomizerPanel`, `addNewTask`, `addNewProject`, `addNewNote`, `focusSideNav`, `toggleSideNavMode`, `openProjectNotes`, `showSearchBar`, `triggerSync`, `showHelp`, zoom.

Press `?` in the app to see your current shortcuts, including unassigned actions, fixed navigation keys, and conflicting bindings. Explicitly saved bindings are kept; missing bindings use the defaults below. The guide and keyboard settings show available suggested replacements for conflicts; choose a suggestion or enter another binding.

## Global Shortcuts

These work everywhere in the app. The keyboard settings list them as **In-app shortcuts**.

- `Shift`+`A`: Open add task bar
- `Shift`+`P`: Open create project dialog
- `Alt`+`N`: Add new note
- `Shift+D`: Focus Sidenav
- `Ctrl`+`B`: Toggle sidebar compact/full mode
- `Shift+N`: Show/Hide Notes
- `C`: Toggle Filter/Group/Sort Panel
- `P`: Open Integrations
- `Ctrl`+`F`: Show search bar (in a browser, this takes precedence over browser Find when the app handles it)
- `B`: Show/Hide Task Backlog
- `W`: Go to Work View and focus first task
- `F`: Enter Focus Mode
- `Shift`+`T`: Go to Today
- `Shift`+`C`: Go to Calendar
- `Shift`+`L`: Go to Upcoming
- `Ctrl`+`,`: Go to Settings
- `Ctrl`+`=`: Zoom in (desktop app only; shown as `Ctrl++` in the settings)
- `Ctrl`+`-`: Zoom out (desktop app only)
- `Ctrl`+`0` (zero): Zoom default (desktop app only)
- `Ctrl`+`S`: Trigger sync (if configured)
- `?`: Show the keyboard shortcut cheat sheet (usually typed as `Shift`+`/`)
- `Ctrl`+`Z`: Undo a supported task change
- `Ctrl`+`Y` or `Ctrl`+`Shift`+`Z`: Redo a supported task change

The cheat sheet lists your current shortcuts, including plugin shortcuts, so it reflects any bindings you have changed in [[3.02-Settings-and-Preferences]]. While left at its `?` default, the shortcut matches the `?` character itself, so it also works on layouts where `?` sits on a different key. Like every other shortcut it can be rebound or removed in the keyboard settings.

The search bar searches open tasks by default, plus tasks deleted on this device in the last 30 days (marked _Deleted_; use its **Restore** button to bring it back). Enable **Include completed and archived tasks** in the search view to include older completed results.

Search is also the keyboard way to places and actions. While the field is empty it lists **Go to** (Today, Inbox, Upcoming and Calendar when they are on, Integrations, Settings) and **Actions** (add a task, Focus mode when enabled, **Set up sync**, the shortcut cheat sheet, and Undo or Redo of the latest supported task change while one is available), with your configured shortcut beside each one that has one. Type to filter them; matching places and actions appear above matching tasks, notes, projects and tags, and the first match is highlighted. **Enter** in the field opens it, and the arrow keys or Tab reach the rest. **Shift+Enter** previews the first matching task, or the focused one, in the side panel without leaving the page you are on; close the panel to go back. **Escape** closes search and returns to where you were.

On macOS, search, settings, sidebar-mode and duplicate-task bindings also accept `Cmd` in place of `Ctrl` when they match the defaults above. Other configured bindings retain their literal modifiers.

- `Ctrl+Enter`: Reveal the note field (or add the task when the note is focused)

### Tag Input (while the tag suggestions are open)

Applies to the tag field in the task detail panel and to the tag pickers in the repeat and issue-provider dialogs.

- `Tab`: After typing, add the highlighted suggestion, or the first one if none is highlighted (on an empty field, `Tab` just moves focus on)
- `Enter`: Add the tag whose name matches the typed text exactly, or create a new tag from the typed text
- `↑` / `↓`: Highlight a suggestion (`Enter` then adds it)
- `Shift+Tab`: Leave the field without adding anything; the typed text is discarded

#### Selecting several tasks

Ctrl+click (Cmd+click on macOS) toggles a task into a multi-selection and Shift+click selects the range from the last toggled task, or from the focused task if nothing is selected yet. While tasks are selected, a bar at the bottom of the list shows the count and an **Actions** menu, and the bulk-capable task shortcuts below act on the whole selection instead of the focused task. See [[2.03-Add-Tasks]] → _Edit several tasks at once_.

- `Shift`+`ArrowDown` / `Shift`+`ArrowUp`: Extend (or shrink) the selection from the focused task by one row
- `X` (configurable as _Toggle task in multi-selection_): Toggle the focused task in the selection
- `Ctrl`+`A` / `Cmd`+`A`: Select every task in the focused task's list
- `Escape`: Clear the selection (when no dialog or menu is open)
- `D`, `Backspace`, `S`, `Shift`+`S`, `Alt`+`T`, `U`, `Shift`+`B`: Apply done, delete, schedule, deadline, add to today, unschedule and move to backlog to every selected task
- `E`, `G`, `T`, `Q`: Open the actions menu for the selection (project, tags, estimate, everything else)
- `Ctrl`+`Shift`+click: Add a range to the existing selection

In the project section view, Shift-click spans visible parent tasks across the root list and sections in displayed order, excluding nested subtasks. Shift+Up/Down and Ctrl/Cmd+A remain within the focused list. Done, backlog, grouped views, and subtask lists retain separate range boundaries.

All other task shortcuts keep acting on the focused task only.

#### Unconfigurable

- `Arrow keys`: Navigate around task list
- In an empty or whitespace-only add-subtask input, `ArrowUp` focuses the preceding subtask or parent task, and `ArrowDown` focuses the next task when available. At the end of the list, focus stays on the closest task row or control.
- `ArrowRight`: Open additional info panel for currently focused task
- `Ctrl`+`Enter` / `Cmd`+`Enter`: Add a subtask to the currently focused task (same as `A`)
- Context-menu key (`Menu`), or `Shift`+`F10` where the browser maps it to that key: Open the task context menu (same as `Q`)
- `Escape`: Unfocus the current task, so the focus outline disappears and the arrow keys stop navigating the list (with tasks selected, the first `Escape` clears the selection and a second one unfocuses the task)

#### Copy, cut, paste, and history

Copy the focused task and its subtasks as a Markdown checklist, or copy a multi-selection in display order. A selected subtask is included only once when its parent is also selected. The shortcut applies when no text is selected and focus is outside an input. Outside the app the clipboard contains plain-text Markdown.

Cut leaves the original in place until a successful paste. Pasting follows one rule for copies and cut parent tasks: the task goes after the focused parent task, or after the parent of a focused subtask, and with nothing focused it goes to the top of the no-section list (a completed task goes to the top of Done). Within the same project this also works in a section, in the backlog and in Done; completed tasks are otherwise ordered by completion time until manually reordered by pasting, dragging, or the task movement shortcuts, and manual ordering does not change their completion times. A cut parent moved to a different project is placed the same way. Paste a cut subtask onto a parent to move it under that parent, or onto a subtask to place it after that sibling. With nothing focused, a cut subtask is promoted to a task at the top of the project you are viewing, including from another project (a subtask of a repeating task can only be promoted within its own project). Direct moves between a section and the backlog are not supported, matching dragging; move the task to the regular list first. If a placement is not possible, a copy stays at the top of the list and a cut task stays where it is.

Copy pastes a duplicate in the same place, after the focused task or at the top of the destination project's list. Several copies keep their order. Completed copies appear in Done according to their completion time. A copied subtask becomes a parent, and time-tracking history, repeat configuration, and issue links are not copied. Task-aware clipboard data is available within the current app session; if it expires, copy or cut again. Copy and cut also work from a focused card in Upcoming and on Boards; paste needs a task list, so open a project or focus a task there.

Copy, cut, paste, undo and redo can be rebound or cleared in keyboard settings. Remapped clipboard commands need browser clipboard permission and support for the browser clipboard API; the standard shortcuts use native clipboard events. On macOS the defaults also accept `Cmd`+`C`, `Cmd`+`X`, `Cmd`+`V`, `Cmd`+`Z` and `Cmd`+`Shift`+`Z`. Text editors keep their own clipboard and undo history while focused.

Session-only history covers estimates on eligible parent tasks; priority, saved notes, and plain titles on eligible parents and subtasks; reordering a single completed project task; and completing or reopening one ordinary task from its checkbox, the keyboard shortcut or the context menu. Completion is left out for repeating tasks, tasks with a reminder, won't-do tasks, linked tasks, and timed tasks when an enabled integration can update calendar blocks, and a completion that also finishes its parent task is not recorded. Priority changes on linked tasks and edits to read-only or stopped integrations can also be recorded. Timed titles and estimates are excluded when an enabled integration can update calendar blocks, as are title edits that short syntax turns into other changes. Scheduling, deletion, general moves, and bulk actions are not in the history. Other persisted actions, incoming sync, and data reload clear the history. The shortcut guide shows the next available undo and redo action.

## Upcoming

Upcoming supports keyboard navigation and task multiselect on overdue, all-day, and timed task cards. Clicking a card focuses it and opens its details. `Tab` focuses a card without opening its details; arrow navigation then starts from that card. Use these keyboard controls:

- `ArrowUp` / `ArrowDown`, or your previous/next task shortcuts (`K` / `J` by default): Move between tasks in the same day.
- `ArrowLeft` / `ArrowRight`: Move to a task in the previous/next day containing tasks.
- `Enter`: Open task details.
- `Ctrl+Shift+Left` / `Ctrl+Shift+Right`: Move the focused task one day earlier or later, preserving its scheduled time and reminder.
- Task shortcuts for completion, time tracking, scheduling, deadlines, unscheduling, deletion, estimates, and the context menu use your configured bindings.
- Task movement shortcuts reorder all-day tasks within their day. Timed tasks keep their time order.

The selection controls listed under _Selecting several tasks_ also work in Upcoming. Shift-click, Shift+Up/Down, and Ctrl/Cmd+A stay within the focused day's tasks, including all-day and timed cards. Overdue tasks form a separate selection group. Ctrl/Cmd-click can build a selection across days. The existing bulk actions menu and bulk-capable shortcuts act on that selection.

Deadline markers, calendar events, and repeat previews are outside task multiselect. The same task can appear both as a task card and a deadline marker. Upcoming's compact cards open details with Enter rather than editing the title inline.

## Boards

Board cards support the Upcoming task shortcuts and the selection controls above.
Click a card or use `Tab` to focus it; double-click or `Enter` opens task details.
On touch devices, a single tap opens task details outside selection mode.
The scheduling icon and its Today/date label appear on the right side of the card.

- `ArrowUp` / `ArrowDown`, or `K` / `J`: Navigate within a panel.
- `ArrowLeft` / `ArrowRight`: Navigate to the visually adjacent panel in the same
  grid row, keeping the task row position where possible. Navigation does not wrap
  to another grid row. An empty panel focuses its add-task button; Left/Right
  from that button continues between panels.
- `Ctrl+Shift+Up` / `Ctrl+Shift+Down`: Reorder within a manually ordered panel.
  Focus stays on the moved card. If the focused card is first, `Ctrl+Shift+Up`
  moves it to the end of the panel directly above, if one exists. An automatically
  sorted destination places it according to its sort order.
  Likewise, `Ctrl+Shift+Down` on the last card moves it to the start of the panel
  directly below, if one exists, keeping focus on that card.
- `Ctrl+Alt+Up` / `Ctrl+Alt+Down`: Move to the top/bottom of a manually ordered panel.
- `Ctrl+Shift+Left` / `Ctrl+Shift+Right`: Move to the visually adjacent panel on
  the left/right, without wrapping to another grid row.

The reorder shortcuts use your configured task movement bindings. When the
focused card is selected, movement applies to the selection. All selected tasks
must be present in the source panel; otherwise moving, reordering and dragging
the selected group do nothing. Dragging a selected card also moves the selection.
Automatically sorted panels accept incoming tasks but keep their configured sort.

Shift-click, Shift+Up/Down and Ctrl/Cmd+A select within one panel. Ctrl/Cmd-click
can select across panels. A task appearing in multiple panels counts once, and
its copies show the same selection. Switching boards clears the selection.
On touch devices, use **Select several tasks…** in a task's context menu, then tap cards
to toggle them; dragging and swiping are suspended during selection.

Moving to a panel applies its filters, just like dragging: tags, project,
completion and scheduling/backlog rules can change. A task can still appear in
its original panel if it matches both panels. If the destination requires
scheduling, one dialog chooses a date for the unscheduled tasks; cancelling it
cancels the move.

## Collapsible Groups

The following shortcuts apply when focus is on a collapsible group header (e.g., task groupings in Work View like From previous days, Today, Done, Recurring, etc.).

- `ArrowLeft`: Collapse the focused group
- `ArrowRight`: Expand the focused group
- `Shift`+`ArrowLeft`: Collapse all groups
- `Shift`+`ArrowRight`: Expand all groups
- `Enter` or `Space`: Toggle the focused group

These shortcuts are **unconfigurable** and always available on group headers.

**Select previous Task** and **Select next Task** also move to the adjacent row from a group header, using your configured bindings (`K` and `J` by default). `ArrowUp` and `ArrowDown` move to the adjacent row as well. Collapsed groups remain navigable, while their hidden tasks are skipped.

## Platform-Specific Differences

**Electron/desktop only:**

- Global shortcuts (`globalShowHide`, `globalToggleTaskStart`, `globalAddNote`, `globalAddTask`, `globalToggleTaskWidget`) work system-wide when the app is running.
- Global Add Task and `ultratasks://add-task` close an open note or task description editor before opening the add-task bar. For a new note with content or unsaved edits to an existing note or task note, a prompt asks whether to **Save** or **Discard**. Dismissing the prompt keeps the editor open without opening the task bar. An unchanged editor closes without a prompt.
- Window zoom controls (`zoomIn`, `zoomOut`, `zoomDefault`) are desktop-only. The web version does not list them in the keyboard settings; in a web browser, the same keys use the browser's own zoom.
- `F11` toggles full-screen mode for the main window.
- `Cmd+W` (macOS only) hides the main window; the app keeps running and clicking the Dock icon brings the window back. This shortcut is unconfigurable.

**Linux (Wayland):**

- Electron's built-in global shortcuts often do not register, because Wayland deliberately leaves global hotkeys to the compositor. Bind your compositor's keys to the URL scheme instead (see below).

**Android:**

- Keyboard settings are not shown on Android; the keyboard configuration UI is hidden.

## Global Shortcuts on Wayland (URL scheme)

On Wayland the compositor — not the application — owns global hotkeys, so the built-in global shortcuts above may not fire. Ultra Tasks registers the `ultratasks://` URL scheme, and the already-running instance handles these URLs, so you can bind compositor keys to them with the standard `xdg-open` command (part of `xdg-utils`, already present on virtually every Linux desktop — no extra tool or runtime to install).

Available fire-and-forget actions:

| URL                                        | Equivalent shortcut     | Effect                                                                                                                                                                                                                                                                               |
| ------------------------------------------ | ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `ultratasks://toggle-visibility`           | `globalShowHide`        | Show/focus the window, or hide it                                                                                                                                                                                                                                                    |
| `ultratasks://add-task`                    | `globalAddTask`         | Show the window and open the add-task bar                                                                                                                                                                                                                                            |
| `ultratasks://add-note`                    | `globalAddNote`         | Show the window and open the add-note dialog                                                                                                                                                                                                                                         |
| `ultratasks://task-toggle-start`           | `globalToggleTaskStart` | Start/pause tracking the current task                                                                                                                                                                                                                                                |
| `ultratasks://create-task/<title>`         | —                       | Create a task with the URL-encoded `<title>` (also accepts `?title=`, `?notes=`, `?projectId=`). Surrounding whitespace is trimmed and Short Syntax is not parsed. See [[3.01-API]] for the full contract.                                                                           |
| `ultratasks://complete-task?title=<title>` | —                       | Complete the single unfinished top-level task matching the URL-encoded `<title>`, which must be a query parameter (there is no path form). Surrounding whitespace is trimmed; an exact match wins, otherwise an unambiguous substring match. See [[3.01-API]] for the full contract. |

Run any of them manually to test:

```bash
xdg-open "ultratasks://toggle-visibility"
```

Then bind them in your compositor. Examples:

```kdl
// Niri (config.kdl)
binds {
    Mod+Shift+S { spawn "xdg-open" "ultratasks://toggle-visibility"; }
    Mod+Shift+A { spawn "xdg-open" "ultratasks://add-task"; }
}
```

```ini
# sway / i3 (~/.config/sway/config)
bindsym $mod+Shift+s exec xdg-open "ultratasks://toggle-visibility"
bindsym $mod+Shift+a exec xdg-open "ultratasks://add-task"
```

```ini
# Hyprland (~/.config/hypr/hyprland.conf)
bind = $mainMod SHIFT, S, exec, xdg-open "ultratasks://toggle-visibility"
bind = $mainMod SHIFT, A, exec, xdg-open "ultratasks://add-task"
```

If `xdg-open` does not reach the app, confirm the desktop entry registers the scheme with `xdg-mime query default x-scheme-handler/ultratasks` (it should print `ultratasks.desktop`). The same mechanism works on X11; it is only required on Wayland.

> **Packaging note:** Ultra Tasks publishes Windows and macOS builds only; on Linux you build the app yourself ([[2.12-Package-the-App]]). The `.deb`/`.rpm` packages register the scheme at install time. With an **AppImage** you must integrate it into your desktop first (e.g. via AppImageLauncher), otherwise nothing registers the scheme.

## Plugin Shortcuts

Plugins can add their own shortcuts. They are listed under **Plugin shortcuts** in the keyboard settings as `<shortcut label> (<plugin id>)` and ship without a default binding, so they do nothing until a key is assigned. Built-in shortcuts take precedence when a combination matches both. Held keys do not repeat — a plugin shortcut runs once per press.

The bundled **Automations** plugin uses this for its _Keyboard Shortcut_ trigger: every enabled rule with that trigger appears as its own entry, named after the rule. Pressing the assigned key runs that rule's actions against the task row currently focused — without a focused task, only task-independent actions (create task, snack, dialog, webhook) do anything.

## Configurable Vs Reserved

All shortcuts listed under **Settings → General → Keyboard shortcuts** are user-configurable. Users can:

- Change any shortcut by clicking the input and pressing the desired key or combination.
- Press **Escape** to leave the field, or **Backspace** or **Delete** to clear an existing binding.
- Have the UI warn when two actions share the same shortcut.

Configurable shortcuts are stored in global config (`GlobalConfigState.keyboard`) and persist to IndexedDB; they sync across devices if sync is enabled. The controls listed as unconfigurable remain fixed.

## Context-Dependent Behavior

**Task-level shortcuts:** Actions with a task focus (e.g. mark done, add subtask, schedule, delete, move) apply to the currently selected task. Selection is by keyboard (tab/arrows) or mouse. The [[3.02-Settings-and-Preferences]] keyboard help text describes these as applying to "the currently selected task."

Specifically for the **Next Month** shortcut, the task is scheduled for the **1st day of the next month**. This avoids issues with different month lengths (e.g., scheduling for the 31st when the next month only has 30 days).

**Calendar week view:** `Ctrl`+MouseWheel changes the vertical scale of the week schedule grid. The value is stored locally for future schedule visits.

**Focus Mode overlay:** `Escape` closes the overlay. If a focus session or break is running, it continues in the header focus button.

**Input filtering:** Application-level and task-level shortcuts are not handled when focus is in an input, textarea, or content-editable element, or when a blocking overlay (e.g. dialog) is open. This avoids shortcuts firing while typing.

## Conflict and Precedence

- **Input focus:** When focus is in an input element or a blocking overlay is open, shortcut handling is skipped so typing is not interrupted.
- **Contextual Precedence:** Task-level shortcuts take precedence over in-app shortcuts when a task is currently focused. Older saved bindings may still assign the same combination to both; review keyboard settings to change them.
- **Conflicts:** The configuration UI warns if two actions are assigned the same key combination. **Escape** leaves the field, while **Backspace** or **Delete** clears an existing assignment.

## Storage and Definition

**Where shortcuts are defined:**

- Config model: `KeyboardConfig` (electron/shared-with-frontend/keyboard-config.model.ts).
- Default mappings: `default-global-config.const.ts` (keyboard section).
- Settings form (which actions appear and their labels): `keyboard-form.const.ts`.

**Where they are stored and used:**

- Saved in `GlobalConfigState.keyboard`; persisted via the global config system to IndexedDB; synced when sync is enabled.
- Handled at runtime by `ShortcutService`; the key listener is registered in the app root (e.g. `AppComponent`).

## Notes

The shortcut system uses the Keyboard API layout map when available so that shortcuts behave correctly across keyboard layouts (e.g. QWERTY, QWERTZ, AZERTY, Dvorak). The user's layout is detected and used for matching key events to configured shortcuts.

# Zen-inspired shell: audit of the Codex work and a combined proposal

**Status:** Proposal for triage, 2026-11-10. WP0–WP4 implemented 2026-11-11 and WP5 delivered as a paper prototype (see [Implementation status](#implementation-status)).
**Reviewed:** commit `04fce5f` ("refine core productivity views") on `main`. The next commit, `8ac83b6` (task clipboard and undo), is outside this scope and was not audited.
**Tracking:** requested repository review; no issue opened.

## Recommendation

Keep the direction. Codex's work is a sound first pass: it is presentation-only, adds no persisted state, operation or sync surface, passes lint and its own specs, and ships E2E coverage for each change. Fix a short list of defects before building on it, then spend the next effort on **subtraction** (the open P1 items of the [Nov 5 audit](../research/2026-11-05-main-interface-ui-ux-audit.md)) and on making **Search** the one place for navigation and quick actions. Decline the parts of Zen that add configuration surface.

One earlier suggestion is retracted: "hide the shell during Focus mode" is moot because the Focus overlay already covers the whole app. Codex improved the overlay instead, which is the better move.

## Evidence and limits

- Ran `04fce5f`/`8ac83b6` in a Chromium dev server at 1440×900, 1100×560 and 390×844, light and dark. Fresh-profile runs used a normal user agent; runs needing Calendar, Boards or Focus mode used the E2E user agent, because [new installs have those off](../../src/app/features/config/new-install-app-features.const.ts).
- `npm run checkFile` on the 30 changed `.ts`/`.scss` files passed. `src/app/t.const.ts` is not linted by root ESLint, so it was not validated.
- Unit specs for the planner, first-run setup and search page passed (8, 5 and 45 tests). E2E specs were **not** run.
- Contrast of the muted empty-state text was sampled from screenshots: about 6:1 in light mode. Dark mode was not measured reliably.
- Not tested: real users, real devices, touch, IME, screen readers, or the Pomodoro cycle counter next to the new clock status line.
- The Zen facts below come from release notes and reviews read in November 2026, not hands-on use or its official docs. The Glance, Essentials and welcome-flow rows rest on background knowledge, not a checked source.
- Per the [shortcuts handoff](2026-11-10-shortcuts-and-undo-handoff.md), the app has no installs yet, so defaults can still change freely. That window is worth using.

## Prior art: Zen Browser

## Combined proposal

**Principles.** Subtract before adding. One surface per job. Presentation only: no new persisted field, operation or schema. A feature that is off by default stays off the critical path.

| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| WP0 | Fix F1–F5, F7, F8 on the existing code. Add one shared ghost-button variant; delete the local copies and the `!important`s.                                                                                                                                                                                               | Keyboard-only first run reaches Continue first; no example task exists before the choice; one empty-state pattern; the diff has no new `!important`. |
| WP1 | The Nov 5 audit's still-open P1 items (duplicate capture destination, header sync setup, page-title link, deleted-result restore; the page-title and restore items were not re-checked on current `main`), plus "Support us" into Help. Keep Inbox only until evidence shows others need triage.                                                                  | Drag and button paths both pass E2E, including reload and a second client; no new persisted state.                                                   |
| WP3 | Search as the command bar: destinations (Today, Inbox, Upcoming, Calendar when enabled, Settings sections) and actions, one list, filtered by the typed text. Then an optional peek (Space) that opens task detail without navigating.                                                                                    | Every destination reachable by keyboard from any page; Esc returns to the prior context; list adds no per-keystroke work on large task sets.         |

**Declined:** mod or theme marketplace, general split view, hover-to-reveal chrome, layout toggles, per-view restyling, a Today filter by context.

**Compatibility.** WP0–WP3 touch no persisted model, operation, vector clock or schema. If any package adds a persisted preference, it needs the [persisted-fields](../sync-and-op-log/persisted-model-fields.md) review first. The clipboard and undo commit (`8ac83b6`) touches `task.model.ts` and issue two-way sync; per the sync rules it needs its own fresh-context review, which this document does not replace.

**Validation matrix for every package.** Light and dark; glass on and off, and reduced transparency; width under 600 px; coarse pointer; reduced motion; a long title and a large list; keyboard-only; screen-reader names for any control that lost its icon-only form.

## Open questions

1. **Integrations in the primary nav by default?** The [unified integrations plan](2026-11-08-unified-integrations.md) decided yes. A fresh install then shows four destinations, one of them for an opt-in feature; showing it once a connection exists would be calmer. Recommendation: disclose progressively, but this overturns a stated decision, so it is the maintainer's call.
2. **Inbox-only triage or all unscheduled tasks?** Recommendation: Inbox only until a user reports needing more; Inbox is the triage queue.
3. **Should first run offer a sync path?** UltraSync sign-ups are temporarily closed, but WebDAV and Dropbox sync are not. Recommendation: yes, folded into Restore.

## Implementation status

WP0–WP2 landed on 2026-11-11 after the maintainer settled the open questions; WP3 and WP4 followed the same day, and WP5 is a paper prototype.

**Decisions taken**

1. **Integrations stays in the primary navigation, but only once something is connected.** The footer Marketplace row moved into Settings: **Plugins & integrations** is a Settings row on every screen size (Account stays a phone-only Settings row). A fresh install keeps the `/integrations` route, the **Open Integrations** shortcut and the Marketplace window's "Go to integrations" button as ways in.
2. **The Upcoming panel lists all unscheduled tasks, with a project filter**, not only the Inbox. It leaves out subtasks, done tasks, hidden integration tasks and each project's backlog, and caps the drawn rows at 100 (the filter narrows a longer list). Its open state and filter are device-local (`LS.PLANNER_UNSCHEDULED_*`), never synced.
3. **First-run sync path (F2)** was deferred first, then built on 2026-11-12 (the "Server collaboration planning" session confirmed it was not building it). The welcome has a fourth card, **Sync from another device**, which opens Settings → Account (`/#/account`); **Set up sync** there opens the existing dialog, so nothing is configured on the user's behalf. Like Restore and Import it seeds no example task. Restore and Import now open Settings by name (`?section=data`, an alias beside the existing `keyboard`, `sound` and `appearance`) instead of `tab: 5`, which would silently point at the wrong tab if the tabs were reordered.

**Deliberate deviations from the wireframes**

- **Header "Set up sync" button (WP1): first deferred, then hidden while no provider is chosen** (2026-11-11). It was left in because several sync E2E helpers open setup by right-clicking it on a fresh profile. It now shows only once sync is on and a provider is chosen, on every screen size (a provider that needs re-authorisation still counts, so the icon stays as the fix). The ways in before that are Settings → Account, the new **Set up sync** action in Search, and the first-run welcome. The affected E2E helpers (`SyncPage.setupWebdavSync`, the SuperSync setup, `legacy-sync-setup`, two settings specs) open setup through Search via `e2e/utils/open-sync-setup.ts`; reconfiguring a configured profile still right-clicks the icon. An earlier version of this note said sync entry points were being reworked in another session; the "Server collaboration planning" session works on the sync service and integrations, not on this UI.
- **Search suggestions (F4) stay until WP3**, which replaces them. Search's hand-rolled row buttons are the one place the F7 cleanup was left for that reason.
- **Phone: empty days stay separate rows but shrink** (one-line header over a slim dashed zone, no planned/available line) instead of merging into one "Wed – Fri" row. Merging would have broken `scrollToDay`, the visible-day observer and the infinite-scroll trigger, which all key off one element per day.
- **F7 used the styling guide's Material buttons** (`mat-flat-button`, `mat-button`, `mat-stroked-button`) rather than a new shared class, and removed the five `!important` rules.
- **The Upcoming toggle sits beside the page title**, not in the right-hand action row, so it needs no new header plumbing.
- **Deleted search results restore only through their Restore button.** Activating the row no longer restores (audit item 5); the page title of special sections is a plain heading (audit item 4).

**WP3–WP5 (2026-11-11)**

- **WP3, Search as a command bar.** Places and actions are one fixed, filterable list above the existing results, replacing the static suggestions; there is still one search. Enter in the field opens the first match. Integrations is always listed, since its navigation row appears only once connected. The optional peek landed as **Shift+Enter** (not Space, which already means "open" on a result button and types a space in the field): it selects the task so its details open in the side panel, and the page behind does not change.
- **WP4, Calendar polish.** Today's header and column are tinted, work start and end are hairlines with a small label, and an empty week shows one muted line with a **Plan unscheduled tasks** action (hidden when Upcoming is off). It was implemented although Calendar is still off for new installs, at the maintainer's request.
- **WP5, context identity.** Delivered as [a paper prototype and test plan](2026-11-11-context-identity-paper-prototype.md), by the maintainer's decision: four variants, the rules they must keep, and a decision rule. Folders are excluded because their tree is synced data and has no colour.

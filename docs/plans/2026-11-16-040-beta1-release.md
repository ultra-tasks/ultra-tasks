# Ultra Tasks 0.4.0-beta.1 release record

The maintainer authorized consolidating every client worktree and uncommitted
product change onto main, fixing observed failures, and publishing the beta for
the supported platforms. Android store submission and promotion are excluded
until the downloaded beta has been tested. iOS TestFlight remains in scope.

## Consolidation

- The E2EE audit and merge worktrees were merged into main. The other named and
  detached client worktrees already had their committed work on main.
- Pending UI/mobile work, tests, documentation and release tooling were committed
  together after file checks and full lint/tooling checks.
- Generated translation keys were regenerated through the owner script. Temporary
  logs, backups and encrypted signing material are not product source and remain
  outside Git and packaged downloads.
- Version: `0.4.0-beta.1`; Android version code: `4000001`.
- Changelog base: published `ultra-tasks-v0.3.0`.

## Review and fixes

Fresh-context review reproduced a stale planning-snackbar failure: task A's old
Undo button unscheduled a later task B. The callback now captures the exact
generic history entry and checks the intended task/day; the direct fallback
rechecks current eligibility. Existing undo actions and replay semantics remain
unchanged. Seventy-one focused unit tests and three real browser cases pass,
including a positive fresh-snackbar control and preserving later priority history.

The task component's hot-path change updates an existing breakpoint dependency.
The inspected new configuration flags are optional presentation metadata, not
new persisted fields. Plugin loading retains decision order and remains below
the existing service-size cap. No schema or public/plugin API change is added by
the consolidation fix.

One native classifier gap remains unverified: `InvalidKeyException` has Android
subclasses that can describe temporary authentication requirements. The current
MasterKey is not configured to require authentication, and no reachable failure
was reproduced. Record it for device testing rather than inventing a recovery
change without evidence.

## Publication boundaries

Desktop workflows receive the public OAuth registrations. They publish suffixed
versions as prereleases without replacing the latest stable release. Packaging
can run with `publish_release=false`; the verified-artifact publisher releases
the accepted packages later. Its GitHub token does not trigger inherited store
workflows.

Android builds are manual with an empty `play_track`: signed standard/F-Droid
APKs and an AAB are produced without Play submission. Web bundles are built
manually for this beta. Apple signing configuration is being completed for a
separate iOS TestFlight upload. Live integration/calendar and physical-device
acceptance remain beta testing work, not claims of completed stable acceptance.

## Beta validation follow-up

The initial remote unit run executed 20,252 Angular cases and found one test
that assumed the package version had no prerelease suffix. The production
version parser intentionally reports the base version for server compatibility;
its test now covers the beta explicitly. The corrected full desktop validation
and standalone web build passed.

The unfiltered scheduled run passed 137 WebDAV cases, 32 released-client cases
and 476 SuperSync cases. Its two SuperSync failures and one regular failure
occurred in browser-test setup: reopening an already-open settings window,
dialog autofocus redirecting a token fill, and editing before task-title focus
settled. The import helper now reuses the window and provider fixtures wait for
the applicable focus handoff. All 17 local provider connection cases pass after
the correction; focused remote reruns verify recovery and owner handoff. These
test changes do not change persisted state, the sync wire or packaged app code.
[Final focused run 44010785074](https://github.com/ultra-tasks/ultra-tasks/actions/runs/44010785074)
passed 23 regular connection/sign-in cases and all five intended sync cases
(four provider owner handoffs and backup recovery). None of these intended
cases was skipped; the separate WebDAV and released-client jobs were omitted
because their unfiltered runs above already passed.

The native iOS smoke passed after allowing the hosted simulator's observed
four-minute cold launch enough time. Both iOS profiles and the distribution
certificate are configured in encrypted Actions secrets. The initial signing
container needed Apple-compatible PKCS#12 encoding; the certificate and key
were preserved. Upload-only iOS builds now use Pilot because Deliver attempted
to read absent App Store review metadata for the new app.

iOS build `0.4.0 (202611170321)` uploaded and finished processing successfully
in [run 44009514936](https://github.com/ultra-tasks/ultra-tasks/actions/runs/44009514936).
It is attached to the external beta group with the maintainer's requested tester
and is **Waiting for Review**. Apple will notify the tester after Beta App Review.
No public TestFlight link is enabled. Android Play upload and store review remain
excluded.
